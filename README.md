# dotfiles — Omarchy × chezmoi

Reproducible Omarchy desktop config. The **files are the source of truth**;
chezmoi is just the courier, and there are no scripts to maintain.

- Omarchy v4 (quattro) · Hyprland · managed with [chezmoi](https://www.chezmoi.io/)
- chezmoi source: `~/.local/share/chezmoi` (this repo) · chezmoi installed via **mise**
- Works on machine `kuldeep` today; add more machines in minutes (see below).

---

## 1. The ownership model (read this first)

Everything on an Omarchy system is one of four zones. This repo tracks only zones 3+4.

| Zone | Who owns it | Examples | In this repo? |
|---|---|---|---|
| 1. Package-owned | omarchy pacman package | `/usr/share/omarchy/**` | ❌ never |
| 2. Generated state | `omarchy theme set`, shell runtime | `~/.local/state/omarchy/**` (terminal colors, background), `~/.cache/omarchy/**`, `*.bak*` | ❌ regenerated by commands |
| 3. Seeded, then yours | you (Omarchy seeds/rewrites rarely) | `~/.config/hypr/*.lua`, `~/.config/omarchy/shell.json`, terminal configs, `~/.bashrc` | ✅ tracked |
| 4. Purely yours | you | custom themes, hooks, extensions, branding, git/starship/tmux/btop, mise config | ✅ tracked |

**Why zone 3 is stable:** Omarchy v4 loads packaged defaults *first*
(`require("default.hypr.omarchy")` from `/usr/share/omarchy/default/hypr/`) and your
files *after* as overrides — "so package updates can improve the defaults without
rewriting your ~/.config/hypr files". Terminal colors are imported at runtime from
`~/.local/state/omarchy/current/theme/`, so tracked terminal configs only contain
fonts, padding and bindings.

**The two writers problem:** only `omarchy update` (rare migrations) and
`omarchy refresh <app>` (manual) rewrite zone-3 files. The
`post-update.d/50-chezmoi-drift-check.hook` hook notifies you after every update;
you then *review and choose* (see §4). Nothing is ever auto-applied or auto-reverted.

## 3. New machine bootstrap (the whole point)

```bash
# 1. Install Omarchy from the ISO (stock install, nothing custom).

# 2. Toolchain bootstrap — mise first, then chezmoi THROUGH mise:
omarchy pkg add mise
mise install chezmoi          # version pinned by dot_config/mise/config.toml

# 3. Deploy everything:
chezmoi init --apply coldter/omarchy-dotfiles
#    → prompts: machine hostname (Enter = current) + theme (Enter = matte-black)
#    → renders per-host templates, copies all configs,
#    → run_once scripts fire: packages install, theme applies, mise tools install

# 4. If run outside a session, finish by hand:
omarchy theme set matte-black
#    then log out / back in.
```

## 4. Daily workflows

### Editing configs (the only habit you need)

```bash
edit files as usual (Omarchy menu, editor, whatever)
chezmoi re-add                 # sync live files → source (or: chezmoi add <path>)
chezmoi git -- add -A && chezmoi git -- commit -m "…" && chezmoi git -- push
```

### After `omarchy update` (reconciliation — review, then choose)

The drift hook fires automatically: notification + full diff saved to
`~/.local/state/chezmoi-drift/<timestamp>.diff`.

```bash
chezmoi diff                   # what Omarchy changed vs. your source
chezmoi re-add                 # Omarchy's change is good → adopt it (then commit+push)
chezmoi apply                  # Omarchy's change is bad  → restore yours
```

Rule of thumb: **`omarchy refresh <app>` → almost always reject** (`chezmoi apply`),
**update migrations → usually adopt** (`chezmoi re-add`), unless they clobber your tweaks.

### Adding a package

```bash
omarchy pkg add <pkg>          # try it first, confirm you like it
echo "<pkg>" >> "$(chezmoi source-path)/packages/manual-packages.txt"   # or aur-packages.txt
chezmoi git -- add -A && chezmoi git -- commit -m "pkg: <pkg>" && chezmoi git -- push
```
Only add what Omarchy doesn't already ship. `omarchy pkg add` is idempotent, so
accidental duplicates are harmless — but keep the list meaningful.

### Adding a dev tool (mise)

```bash
mise use -g <tool>@<version>   # writes ~/.config/mise/config.toml (tracked)
chezmoi re-add && chezmoi git -- add -A && chezmoi git -- commit -m "mise: <tool>" && chezmoi git -- push
```

## 5. Machine-specific config: `monitors.lua.tmpl`

`dot_config/hypr/monitors.lua.tmpl` is the only templated config. It contains one
Lua block per machine hostname; chezmoi renders **only the matching block** into
`~/.config/hypr/monitors.lua`. Unknown hostnames get the generic fallback block,
so a fresh machine always boots with a working display config.

To add machine `laptop-2`:

1. On that machine: `hyprctl monitors all` (outputs, modes, positions)
2. Edit the template: `chezmoi edit ~/.config/hypr/monitors.lua`
3. Insert a block: `{{ else if eq .hostname "laptop-2" }} … your hl.monitor() lines …`
4. Render + reload: `chezmoi apply ~/.config/hypr/monitors.lua`
5. Commit: `chezmoi git -- add -A && chezmoi git -- commit -m "monitors: laptop-2"`

The hostname comes from `~/.config/chezmoi/chezmoi.toml` `[data] hostname`
(prompted during `chezmoi init`). Other per-machine deltas (input.lua, autostart)
can become templates the same way — only do it when machines actually diverge.

## 6. Themes

Your custom themes live in `~/.config/omarchy/themes/<name>/` (tracked, zone 4).
Theme *colors* applied to terminals/btop/etc. are **generated** into
`~/.local/state/omarchy/current/theme/` by `omarchy theme set` — never tracked,
always regenerated (`run_once_after_20-theme.sh` on new machines, or manually).
Current theme name is also stored per-machine in `chezmoi.toml` `[data] themeName`.

## 7. Safety rules (this is a PUBLIC repo)

chezmoi is opt-in — only explicitly added files are tracked. Still:

- **Never track:** `~/.config/gh/` (OAuth token), `~/.ssh/`, `~/.local/share/opencode/`
  (auth.json), `~/.config/environment.d` secrets, `*.local`, anything token-shaped
- Before pushing something new: `chezmoi managed | xargs grep -lEi 'token|secret|api[_-]?key'`
- Edit secrets-adjacent configs in place without `chezmoi add` — they simply stay unmanaged

## 8. For AI agents

**Vendored skill (read first):** this repo ships `chezmoi-workflows` at
`.agents/skills/chezmoi-workflows/SKILL.md` (installed via `npx skills add terrylica/cc-skills --skill chezmoi-workflows`, pinned by `skills-lock.json`).
Agents working in this repo should read it and follow its workflows — in
particular **Status Check (§1)**, **Safe Update / diff-before-apply (§13)** and
**Validation (§10)**: `chezmoi status` → `chezmoi diff` → explicit
`chezmoi re-add` / `chezmoi apply` → `chezmoi verify`. Never blind-`apply`.

Operating rules when working on this machine's dotfiles:

1. Source of truth edits happen via the live files + `chezmoi re-add`
   (or `chezmoi edit <target>`, which edits source and applies on save).
2. **Never** edit rendered output of `*.tmpl` files directly
   (`~/.config/hypr/monitors.lua`) — edit the template in source.
3. After any Omarchy update/refresh: run `chezmoi diff`, report the drift to the
   user, then `chezmoi re-add` (adopt) or `chezmoi apply` (reject) per their call.
   Never apply/revert without asking.
4. New files belong in the tracked set only after the user confirms they're
   wanted on every machine (zone 3/4 only — see §1).
5. Validate Hyprland changes: `hyprctl reload && hyprctl configerrors` (must be empty).
6. Commit messages: short, lowercase prefix (`pkg:`, `mise:`, `monitors:`, `hypr:`, `omarchy:`).
7. The drift hook must always exit 0 and never apply changes — keep it that way.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| Terminal lost colors after restore | `omarchy theme set <name>` (regenerates zone-2 state) |
| `chezmoi diff` shows noise after every update | Omarchy rewrote a managed file — reconcile (§4) |
| `omarchy refresh` broke tweaks | `chezmoi apply <path>` restores yours |
| New machine missing a package | Add to `packages/*.txt`, run `run_once_after_10-packages.sh` manually |
| `chezmoi status` lists a file you don't want tracked | `chezmoi forget <path>` (keeps the live file) |
